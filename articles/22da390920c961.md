## はじめに

こんにちは！

先日、Pull Requestをレビューしていて、あることに気が付きました。
あるルールだけめっちゃ`eslint-disable`されていることに...😱
その、「あるルール」とは、`no-magic-numbers`というルールでした。

`eslint-disable`しまくるならルールを指定している意味をなさないのではと考え、今後の対処方法をチームで議論しました。

本記事では、`no-magic-numbers`というルールを例に、仕組みの理解やオプション指定による、**ちっちゃな開発体験向上**の具体例について整理したいと思います。

:::message
本記事において、「ESLintとは何か？」といった内容には触れておりません。
:::

## 検証環境

本記事の検証環境における`eslint`のバージョンは、`9.14.0`です。
エディタは、Visual Studio Code（通称：VSCode）を使用しています。

## no-magic-numbersとは

その名の通り、マジックナンバーに関するルールです。
マジックナンバーとは、明確な意味を持たずにコード内で複数回出てくる数字のことです。

> The `no-magic-numbers` rule aims to make code more readable and refactoring easier by ensuring that special numbers are declared as constants to make their meaning explicit.

上記のように`no-magic-numbers`は、数字の意味を明示的にするために定数として宣言することで、コードの可読性を高めたり、リファクタリングしやすくするためのルールです。

### 設定の仕方

`eslint.config.mjs`で設定できます。

```javascript
export default [
  {
    files: ["**/*.ts"],
    rules: {
      // ここにルールを追加する
    },
  },
];
```

本記事で掲載している設定例は、簡略化しているので、実際の開発現場ではもっと色々な設定を入れているかと思います。
本記事のテーマである、`no-magic-numbers`を追加する場合は、以下のようにします。

```javascript
export default [
  {
    files: ["**/*.ts"],
    rules: {
      "no-magic-numbers": "error",
    },
  },
];
```

今回`error`としています。`no-magic-numbers`だけに限らずESLintどのルールについても言えることですが、`warn`にして警告を出す程度に留めることも可能です。

### 確認方法

ルールを設定したら、コードがルールを守っているかどうか、以下のような方法でチェックすることができます。

- `npx eslint 対象ファイル`というコマンド
- エディタの拡張機能

今回はESLint自体の解説記事ではないので細かい説明は省かせていただきます。

### コードの例

```typescript
const points = purchaseAmount * 0.03;
```

コード例を見ると、`0.03`という何を意味するかわからない**マジックナンバー**が使われています。
他の変数名を見てなんとなく、ポイントを算出してそうだなーってことがわかる程度です。
※実際には端数処理などの処理が必要かと思いますが、簡略化のため省略しています。

`no-magic-numbers`を設定している状態でESLintチェックコマンドを実行してみると、次のようにエラーになります。

```
4:33  error  No magic number: 0.03  no-magic-numbers
```

また、VSCodeのESLint拡張機能を入れている場合は、エディタでも次のようにエラーが出てきます。
![](https://static.zenn.studio/user-upload/08a9ec0b6c69-20260619.png)

このエラーを解消するためには、マジックナンバーにしている部分を定数定義し、意味を持たせる必要があります。

```typescript
// Good✅
const POINT_RATE = 0.03;
const points = purchaseAmount * POINT_RATE;

// Bad❌
// const points = purchaseAmount * 0.03;
```

`0.03`とマジックナンバーを使っていたところを、`POINT_RATE`という定数を定義しています。
`0.03`としていたところをこの定数`POINT_RATE`に置き換えることでマジックナンバーを使った実装が消え、エラーを解消することができます。

## 設定で工夫できること

`no-magic-numbers`には、様々なオプションが存在します。
オプションを指定することで、ルールを緩和することができます。

| オプション名                  | 説明                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| ignore                        | 特定の数字を許容するか                                                                                           |
| ignoreArrayIndexes            | 配列のインデックスの数字を許容するか                                                                             |
| ignoreDefaultValues           | 関数の引数のデフォルト値を許容するか<br>※useStateは対象外                                                        |
| enforceConst                  | 数字をconstで定義するように制限するか                                                                            |
| detectObjects                 | オブジェクトの値で使われている数字を許容するか                                                                   |
| ignoreEnums                   | enumで使われている数字を許容するか<br>※`@typescript-eslint/no-magic-numbers`を使う                               |
| ignoreNumericLiteralTypes     | リテラル型で使われている数字を許容するか<br>※`@typescript-eslint/no-magic-numbers`を使う                         |
| ignoreTypeIndexes             | インデックスアクセス型のインデックスの数字を許容するか<br>※`@typescript-eslint/no-magic-numbers`を使う           |
| ignoreReadonlyClassProperties | readonlyと定義されたクラスプロパティ内の数値リテラルを許容するか<br>※`@typescript-eslint/no-magic-numbers`を使う |
| ignoreClassFieldInitialValues | クラスのフィールド定義の初期値の数字を許容するか                                                                 |

上記の表にあるようなオプションを指定することによって、「この場合のマジックナンバーは許容して、それ以外は検知する」といった調整をすることができます。もちろん、複数のオプションを組み合わせることも可能です。

### 試しにオプション指定やってみる

先ほどのポイント算出のコードを用いて、試しにオプションを指定してみます。
例えば、以下のようにオプションを指定します。

```javascript
export default [
  {
    files: ["**/*.ts"],
    rules: {
      "no-magic-numbers": [
        "error",
        {
          ignore: [0, 1], // 0, 1を許容
        },
      ],
    },
  },
];
```

ここでは、`ignore`という特定の数字（0・1）の使用を認めるオプションを指定しています。

以下のコードでは、先ほどのポイント算出の処理に加えて、来店ボーナスを1ポイント加算する処理を実装しています。
`if文`の条件で`0`を使っていたり、来店ボーナスを加算するため`1`が使われています。

```typescript
const POINT_RATE = 0.03;
let points; // ignoreの挙動に注目するため初期値代入を省いた

if (purchaseAmount > 0) {
  points = purchaseAmount * POINT_RATE + 1;
  console.log(points);
}
```

この状態でESLintチェックしてみるとどうなるでしょうか。
コマンドを実行してみても、エラーは出ません。

VSCodeのESLint拡張機能を入れているので、エディタではどうなっているのか見てみます。
![](https://static.zenn.studio/user-upload/08079044722d-20260622.png)
前出のコード例で出ていたような、赤の下線と`no-magic-number`のエラーは出ていません。
これは、`ignore`オプションを使って`0`と`1`の使用を認めたからです。

このようにオプションを指定することにより、`no-magic-numbers`のルールを緩和し、より開発しやすい設定へと調整することができます。

### typescript-eslint

`typescript-eslint`についても軽く触れておこうと思います。

> Tooling which enables you to use TypeScript with ESLint

「ESLintでTypeScriptを使用できるようにするためのツール」、つまり、型情報を含むTypeScript独自のコードも構文チェックできるようにするツールということです。

ESLintがベースになっており、`typescript-eslint`でESLintのルールはカバーできます。そのため、`typescript-eslint`を使う場合は通常のルールを`off`にしておく必要があります。
例えば、`eslint.config.mjs`では次のように記述します。

```javascript
import typescripteslint from "typescript-eslint";

export default [
  ...typescripteslint.configs.recommended,
  {
    files: ["**/*.ts"],
    rules: {
      "no-magic-numbers": "off", // typescript-eslintを使うのでこっちはoffにする
      "@typescript-eslint/no-magic-numbers": [
        "error",
        {
          // オプションを追加する
        },
      ],
    },
  },
];
```

上記の設定を見てみると、`@typescript-eslint/no-magic-numbers`が使われています。これが、`typescript-eslint`です。
`no-magic-numbers`の場合は、型を判別できるようになり、マジックナンバーの誤検知を防ぐことができます。
今回の`no-magic-numbers`の場合、`typescript-eslint`を導入することにより、以下のオプションを利用できるようになります。

- `ignoreEnums`
- `ignoreNumericLiteralTypes`
- `ignoreTypeIndexes`
- `ignoreReadonlyClassProperties`

`enum`や数値のユニオン型、インデックスアクセス型のインデックス番号、`readonly`が付いたクラスのプロパティといったTypeScriptの型情報に関する数字を、通常のマジックナンバーと区別することができます。

## 許容されている数字

設定に関わらず、使用を認められているマジックナンバーも存在します。
以下の2種類については、オプション指定せずともマジックナンバーで記述することが可能です。

- `parseInt()`の第2引数（基数）
- JSX内の数字

`no-magic-numbers`のコードを確認してみます。
`parseInt()`の第2引数（基数）とJSX内の数字の判定を行う実装がされていることがわかります。
https://github.com/eslint/eslint/blob/14be92b6d1fa0923b8923830f2208e5e2705b002/lib/rules/no-magic-numbers.js#L224-L253

そして、マジックナンバーを許容する条件分岐を見てみます。
`parseInt()`の第2引数（基数）とJSX内の数字は許容されることになっています。他の条件とは異なり、オプション設定の状態を見ていないことからも、設定状況に関わらず、常に許容されていることがわかります。
https://github.com/eslint/eslint/blob/14be92b6d1fa0923b8923830f2208e5e2705b002/lib/rules/no-magic-numbers.js#L321-L340

### `parseInt()`の第2引数（基数）

基数とは、10進数や16進数といった、数値を表現するための基準となる数のことです。
JavaScriptの関数で、いくつか基数を指定する関数が存在します。そのうちの、`parseInt()`という文字列の数字を整数に変換する関数の第2引数に渡す基数は、このルールの設定状況やオプション指定に関わらず、認められます。

```javascript
const parsedIntValue = parseInt("123", 10); // 123
```

上記のように、`parseInt()`の第2引数に`10`という数字がべた書きされています。これが、基数です。
しかし、`parseInt()`の第2引数（基数）はマジックナンバーの使用が認められているので、オプション設定をせずともエラーにはなりません。
![](https://static.zenn.studio/user-upload/c0b7dbf4a980-20260615.png)

他にも、数値を文字列に変換する`toString()`関数も引数に基数を渡しますが、こちらはマジックナンバーの使用が認められていません。そのため、同じ
基数であっても、`no-magic-numbers`のルールのため検知されてしまいます。

### JSX内の数字

これは、ReactやNext.jsなどでJSXを記述した時に使う数字です。

```jsx
<input type="text" maxLength={150} />
```

上記のように、`maxLength={150}`というような数字`150`がべた書きされていますが、こちらもオプション設定をせずとも検知されません。

## チームでの取り組み

では、実際にチームではどのように対応していくことになったのかについてお話しします。

### 対応案

以下の2つの対応案を提案しました。

1. ルールから外す
2. ルールに残したままオプションで調整する

「1. ルールから外す」は、`no-magic-numbers`というルール自体を取り除いてしまうという対応で、コメントを消していくだけで対応としては楽です。ただし、マジックナンバーを検知した方が良いコードであっても検知されなくなるため、実装者自身やレビュアーの意識ベースでの対応に頼ることになってしまいます。

それに対し、「2. ルールに残したままオプションで調整する」は、「設定で工夫できること」の項目でご説明したようなオプションを使ってルールを緩和する方法です。

### 議論の結果...

チームで話し合った結果、**「2. ルールに残したままオプションで調整する」** ことになりました。
よく使っているパターンは許容しつつも、本当に定数化すべきところはエラーとして出してもらうべきで、オプションで調整した方が良いという結論になりました。

- `ignoreArrayIndexes`
- `ignoreNumericLiteralTypes`
- `ignoreTypeIndexes`

どのオプションを指定するかは、主に「よく使っているものはどれか」という観点から意見が出ました。
（実際には、これら3つのオプションに関係する部分以外でも`eslint-disable`しています。）
これらをオプション指定する場合、以下のようになります。

```javascript
import typescripteslint from "typescript-eslint";

export default [
  ...typescripteslint.configs.recommended,
  {
    files: ["**/*.ts"],
    rules: {
      "no-magic-numbers": "off",
      "@typescript-eslint/no-magic-numbers": [
        "error",
        {
          ignoreArrayIndexes: true,
          ignoreNumericLiteralTypes: true,
          ignoreTypeIndexes: true,
        },
      ],
    },
  },
];
```

デフォルトが`false`で、今回`true`にしたことにより、配列のインデックス番号や数値リテラル型の数字、インデックスアクセス型のインデックス番号をマジックナンバーで記述することを許容しました。

今まで`eslint-disable`していたところを一気に直すのは大変なので、こまめに`eslint-disable`を解消する対応をしていくことになりました。

## おわりに

せっかくESLintルール設定したのに、`eslint-disable`で握りつぶしてしまってはもったいないと思います。きちんと対応すればコードの質を高めることができます。
`eslint-disable`してしまっているのは、「いちいち検知されるのが面倒」なのか「ただ対応するのが手間になってしまっている」のかなど色々な事情があると思います。そんな時は、コードやチームの状況に応じて、オプションで調整するという手段を検討してみるのが良いと考えます。

今回、私のチームでも、`no-magic-numbers`というルールをオプション指定をして調整し、開発しやすくなるよう工夫を行いました。これにより、コードの質を高めることにつながったら良いなと思っています。

本記事で扱った`no-magic-numbers`以外でもオプションがあるルールは存在します。他のルールでも同じような課題に直面している方の参考になれば嬉しいです！
お読み下さり、ありがとうございました！
